# AML Transaction Monitoring — Fraud Detection Project

A end-to-end Anti-Money Laundering (AML) analytics project using two real-world Kaggle datasets. Covers SQL-based aggregation, Python risk scoring, and a Power BI dashboard to identify high-risk accounts and suspicious transaction patterns.

---

## Problem

Financial institutions process millions of transactions daily with no scalable way to distinguish legitimate activity from fraud or money laundering. Manual review is slow, expensive, and misses behavioral patterns hidden in volume.

## Approach

| Tool | Usage |
|------|-------|
| **SQL** | Aggregate transactions per account, rolling averages, anomaly flags using window functions |
| **Python** | Data cleaning, statistical risk scoring, 3-tier segmentation (Low / Medium / High) |
| **Power BI** | Risk dashboard — flagged transactions, fraud trends, account heatmaps |
| **Excel** | Initial data profiling, null handling, distribution checks |

## Datasets

| Dataset | Source | Rows | Description |
|---------|--------|------|-------------|
| `creditcard.csv` | [Kaggle — Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud) | 284,807 | Anonymised PCA features + transaction amount + fraud label |
| `PS_20174392719_1491204439457_log.csv` | [Kaggle — PaySim Synthetic Financial Dataset](https://www.kaggle.com/datasets/ealaxi/paysim1) | 6,362,620 | Synthetic mobile money transactions with fraud labels |

> Download both CSVs from Kaggle and place them in `data/raw/` before running any scripts.

## Key Findings

### Credit Card Dataset
- Fraud peaks at **2am–4am** — fraud rate of 1.71% at 2am vs 0.09% during business hours
- Fraudulent transactions average **$122** vs $88 for normal — a 38% premium
- Only **492 confirmed fraud** out of 284,807 (0.17%) — severe class imbalance
- Combining amount spike flag (>3σ) with confirmed fraud covers the entire fraud population with a 4,500-transaction review queue

### PaySim Dataset
- Fraud is concentrated in exactly **two transaction types**: TRANSFER (0.77% fraud rate) and CASH_OUT (0.18%)
- CASH_IN, PAYMENT, and DEBIT have **zero confirmed fraud**
- The built-in `isFlaggedFraud` system caught only **16 of 8,213** real fraud cases — a 99.8% miss rate
- Risk segmentation reduces the investigation queue from **6.36M → 8,299 accounts** (99.87% reduction)

## Quick Start

```bash
# 1. Clone the repo
git clone https://github.com/YOUR_USERNAME/aml-transaction-monitoring
cd aml-transaction-monitoring

# 2. Install dependencies
pip install -r requirements.txt

# 3. Add data (download from Kaggle links above)
# Place files in data/raw/

# 4. Run EDA
python python/01_eda.py

# 5. Generate risk scores
python python/02_risk_scoring.py

# 6. Export flagged accounts
python python/03_export_flagged.py

# 7. Open dashboard
open dashboard/aml_dashboard.html
```
